## 今回の IB 経路

`serve logs` は欠落 0 件。所有ラベルと構成名で確認したコンテナだけから hostname と開始時刻を読み、
今回の時刻に一致する `nccl.spark-153d.342.log` と `nccl.spark-5083.287.log` を選んだ。
両台それぞれに経路確定行が 2 件あり、すべて `Using network IB` だった。
`tp2-containers.json` と `tp2-nccl-verdict.json` に帰属と判定だけを記録した。
コンテナの hostname はこの環境ではホスト名と同じだったため、名前だけで過去分と区別せず開始時刻も照合した。
同じ名前の NCCL ログは次の起動で上書きされる仕様なので、初回分は Mac に回収済みのコピーを保持する
（[NVIDIA の NCCL_DEBUG_FILE の説明](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/env.html#nccl-debug-file)）。

## 64 トークンでの短い応答と停止

`serve smoke` の HTTP は両方 200、CLI は `status=answered` だった。ただし**日本語の回答本文が空であり、
短い応答 2 件の合格条件は未達**である。HTTP や CLI 終了値だけで成功扱いにしていない。

| 言語 | 入力トークン | 出力トークン | 停止理由 | 本文と判定 |
|---|---:|---:|---|---|
| 英語 | 25 | 40 | end_turn | 本文あり。意味が通る |
| 日本語 | 28 | 64 | max_tokens | text ブロックなし。意味を判定できない |

出力上限は既定の 64。本文や思考内容は保存せず、上表の事実だけを `tp2-smoke-verdict.json` に記録した。
空の本文の原因を思考の長さだけとは断定しない。
ログを再回収して欠落 0 件を確認し、所有と構成を照合して `serve stop --yes` で停止した。
`status=stopped`、`remaining_gpu_apps=0`。両台の自分たちのコンテナは削除済み。
