# K1: MTP の下書きのトークン数（N = 2、3）の探りと確認

日付は 2026-09-25 JST。N = 1 の記録（[2026-09-25-k1-mtp1.md](2026-09-25-k1-mtp1.md)）の続き。
2 つの上限（GPU 1800 MHz、X925 3.0 GHz）は、どの回も両台で効いていた。実機操作は対話側が行った。

計測は、待ち時間を短くするために 3 段に分けた（`bench/README.md`）。

- **探り**（`probe`。decode は出力 128 トークン、quality は 7 要求）: 1 回約 5 分。
- **確認**（`fast`。decode は出力 256 トークン、concurrency は 1・2・4 本、quality は 22 要求）: 1 回約 15 分。

どちらも起動に約 11 分かかる（#37）。`serve watch` の最初の記録までにも約 3 分かかる（#41）。

## 要約

- 暫定の既定は **N = 3** とする。同じ出力の長さ（128 トークン）で比べると、N = 3 は N = 2 より 7〜13% 速い。
- **受理長は、出力の長さで大きく変わる。** N = 3 の code/en の受理長は、出力 128 トークンで 3.73、出力 256 トークンで 3.09 だった。tok/s も 34.0 から 27.8 に下がった。出力の最初のほうは予測しやすい。N を比べるときは、出力の長さをそろえる。
- 下書きを 1 つ増やすごとに、1 ステップが 14〜18 ms 伸びる（推定。下の表）。当たり率は、日本語と散文で先に落ちる。そのため、MTP だけでは code/en で 30 tok/s 前後が限界と見る。
- humaneval+ は、出力の上限を 2048 にしたら、10 問とも上限の前に答え終わり、10/10 だった。N = 1 の記録で見た低下（26 → 22/40）は、上限 1024 の打ち切りによるものと判断する。
- 壊れの印（`repetition_loop`、`replacement_char`）は、どの回も 0 件。needle は 8k・32k とも正解。toolcall は、確認の 10 問の正解・不正解が、投機なしの回（2026-09-23）と 1 問も変わらなかった。

## 探り（出力 128 トークン）

要約は、N = 2 が [decode](20260925T090427Z-p2-nope-tp2-mtp2-v32gk3/summary.md)・[quality](20260925T090821Z-p2-nope-tp2-mtp2-594n45/summary.md)、N = 3 が [decode](20260925T092555Z-p2-nope-tp2-mtp3-3v6rc4/summary.md)・[quality](20260925T092931Z-p2-nope-tp2-mtp3-zcb8ev/summary.md)。tok/s は中央値。

| 条件 | N = 2 の tok/s | N = 2 の受理長 | N = 2 の当たり率 | N = 3 の tok/s | N = 3 の受理長 | N = 3 の当たり率 |
|---|---:|---:|---:|---:|---:|---:|
| `decode/code/en` | 29.963 | 2.863 | 0.931 | 33.986 | 3.732 | 0.911 |
| `decode/code/ja` | 27.198 | 2.664 | 0.832 | 29.312 | 3.218 | 0.739 |
| `decode/prose/en` | 28.554 | 2.703 | 0.852 | 29.752 | 3.269 | 0.756 |
| `decode/prose/ja` | 26.108 | 2.563 | 0.781 | 27.854 | 3.015 | 0.672 |

1 ステップの時間を「受理長 ÷ tok/s」で推定すると、code/en で次のとおり。N = 0 と N = 1 は出力 1024 トークンの値（N = 1 の記録）で、長さがそろっていないので目安である。

## 確認（N = 3、出力 256 トークン）

| 条件 | tok/s | 受理長 | 当たり率 |

| `decode/code/ja` | 26.723 | 2.939 | 0.646 |
| `decode/prose/en` | 27.251 | 2.934 | 0.645 |

## 熱と上限

| 回 | GPU の最高 | 熱区域の最高 |
|---|---|---|
| N = 2 の探り | 52℃ / 52℃ | 59.7℃ / 55.7℃ |
| N = 3 の探り | 53℃ / 52℃ | 60.0℃ / 56.1℃ |
| N = 3 の確認 | 58℃ / 57℃ | 64.1℃ / 60.7℃ |

値は head / worker。SM は 1761〜1781 MHz、X925 の上限は両台 3,000,000 kHz だった。`serve watch` の `events` は空だった。
N = 2 の探りでは、92℃ の安全停止の見張りが bench のプロセスを見つけられず、動いていなかった（台本の不具合。以後は、見張りを付けられなければ計測を始めずに止める）。
