# K2: 1 ステップの GPU の時間の内訳（`p2-nope-tp2-mtp3-prof`、MTP の N = 3）

日付は 2026-09-26 JST。[投機なしの内訳](2026-09-26-k2-profile-full.md)と同じ手順で、MTP の N = 3 の構成を測った。
構成は `p2-nope-tp2-mtp3-prof` で、次の設定を使った。

- 重みの読み込みは `instanttensor`（#53）。起動は約 3 分だった。
- プロファイラーは、スタックの記録と表の書き出しを切ったもの（#52）。

2 つの上限（GPU 1800 MHz、X925 3.0 GHz）は、両台で効いていた。実機操作は対話側が行った。

## 要約

- **MTP の検証では、MoE の専門家の GEMM が約 2.8 倍になる。** 1 ステップあたりの呼び出しの回数はほぼ同じで（85 → 89 回）、1 回あたりが 179 µs から 476 µs に伸びた。4 トークンを一度に検証すると、トークンごとに違う専門家が選ばれ、読む専門家の重みが増えるためと見る。
- **BF16 の本体の重みは、GEMV から GEMM に変わる。** cuBLAS の `gemvx`（1 ステップ 335 回）が、`cutlass_80_wmma` の GEMM（384 回、1 回 125 µs）に変わり、合計は約 48 ms だった。投機なしの 52 ms とほぼ同じ。
- **下書きの側で、BF16 の大きな GEMV が 1 ステップ約 14 ms ある。** 1 回 779 µs で、18 回/ステップ。下書きのたびに読む lm_head と見る（推測。形はまだ確かめていない）。
- **カーネルのない隙間が 1 ステップ約 16 ms ある。** 投機なしでは 2.6 ms だった。下書きのループの CPU の処理や同期と見る（推測）。
- K2 との関係:
  - BF16 の部分（本体の約 48 ms と、下書きの約 14 ms）を量子化すると、N = 3 でも大きく効く。
  - MoE の約 42 ms は、K2 では減らない。
  - lm_head の量子化は、下書きのたびに効くので、N = 3 では優先度が上がる。

## 計測の条件と注意

- 計測の窓で、`serve smoke --max-tokens 256` を流した。応答が短く、窓は 4.4 秒・32 ステップだった。prefill の回を 2 回含むので、1 ステップの平均（約 138 ms）は、プロファイラーを付けない計測（約 111 ms、[記録](2026-09-25-k1-n-sweep.md)の受理長と tok/s からの推定）より長い。区分の比べ方は、割合と 1 回あたりの時間で読む。
- head の trace も取れた（前回の OOM は起きなかった）。head と worker の区分ごとの値は、ほぼ一致した（NCCL だけ約 3% の差）。
- **本文の確認は、要求の側だけ。**
  - 要求の語（`capital of France`、`日本の首都`）は、trace の中で 0 件だった。
  - 応答の側は、確認できていない。台本が応答の本文（stderr に出る）を捨てていたため。これは投機なしの回も同じで、どちらの回の確認も効いていなかった。台本は直した。
  - trace は `serving/var/`（Git 対象外）に留める。

## 内訳（worker の rank 1、1 ステップあたり）

`summarize_trace.py` の区分（#52）の値。

| 区分 | N = 0（投機なし） | N = 3 |
|---|---:|---:|
| BF16 の重みの GEMV・GEMM | 52.2 ms | 63.0 ms |
| MoE の専門家の GEMM | 15.2 ms | 42.5 ms |
| MoE の周辺 | 2.5 ms | 2.4 ms |
| アテンションの本体 | 1.3 ms | 2.8 ms |
| mHC | 1.7 ms | 2.1 ms |
| NCCL | 3.0 ms | 8.4 ms |
| その他 | 0.7 ms | 7.9 ms |
| カーネルのない隙間 | 2.6 ms | 15.7 ms |
| 1 ステップ（窓の長さ ÷ ステップ数） | 75.4 ms | 137.7 ms |

N = 3 の「その他」の大半は、`deep_gemm::sm120_fp8_fp4_gemm`（1 ステップ約 5.0 ms）と、`gemmSN_NN_kernel`（fp32）だった。

主なカーネルの、1 ステップあたりの回数と時間:

| カーネル | N = 0 | N = 3 |
|---|---|---|
| NVFP4 の MoE の grouped GEMM | 85.3 回、15.2 ms（1 回 179 µs） | 89.2 回、42.5 ms（1 回 476 µs） |
| cuBLAS `gemvx`（BF16） | 335 回、49.8 ms（1 回 149 µs） | 18.1 回、14.1 ms（1 回 779 µs） |
| `cutlass_80_wmma`（BF16 GEMM） | 24.4 回、1.9 ms | 384 回、48.1 ms（1 回 125 µs） |
| `deep_gemm` fp8 × fp4 | 13.0 回、0.1 ms | 25.8 回、5.0 ms |

## 次に確かめること

1. 下書きの側の大きな GEMV（1 回 779 µs）が lm_head かを、形で確かめる。trace の `record_shapes` を使うか、`profiler_out` を読む。
2. 隙間の約 16 ms の中身（下書きのループの CPU の処理か、同期か）。
3. K2 の見積もりを、N = 3 の内訳で作り直す。BF16 の部分の約 62 ms を FP8 にすると、約 31 ms が減る見込み（推定）。
