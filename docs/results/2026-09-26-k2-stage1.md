# K2 第 1 段: dense と共有の専門家を FP8 にした重み（`k2s1b`）の探り

日付は 2026-09-26 JST。[手順](../vllm-baseline/k2-derived-weights-procedure.md)に沿って、今の重み（`RedHatAI/GLM-5.3-Flash-NVFP4`、rev `18d55bfd…`）から派生の重みを作り、探り（`probe`、出力 128 トークン）で速さと壊れを見た。
2 つの上限（GPU 1800 MHz、X925 3.0 GHz）は、どの回も両台で効いていた。実機操作は対話側が行った。

## 要約

- **投機なしで 9〜11% 速くなった。** decode は 13.9〜14.1 → 15.2〜15.4 tok/s。1 ステップは約 71 ms から約 65 ms になった。事前の見積もり（約 6 ms、約 8%。[調査](../research/2026-09-26-k2-quant-survey.md)）と合う。
- **MTP の N = 3 では 2〜5% 速くなった。** code/en は 34.0 → 34.8 tok/s、prose/ja は 27.9 → 28.8 tok/s。受理長は変わらない（3.0〜3.7）。N = 3 の伸びが小さいのは、下書きのたびに読む lm_head（1 回 779 µs。[内訳](2026-09-26-k2-profile-mtp3.md)）を、この段では FP8 にできなかったため（下の「lm_head」）。
- **壊れは見つからなかった。** toolcall の 5 問は、正解・不正解が投機なしの基準の回と同じだった。needle 8k は正解。`repetition_loop` と `replacement_char` の印は 0 件。探りの規模なので、品質の判断は確認・記録の段で行う。
- 重みを FP8 にする流れ（変換 → 取り込み → 照合 → vLLM で読み込み）は、vLLM を直さずに通った。

## 作った重み

| 項目 | 値 |
|---|---|
| 名前 | `k2s1b` |
| 対象 | dense の MLP（層 0〜2）の 9 射影、共有の専門家（層 3〜45）の 129 射影。計 138 モジュール |
| 形式 | FP8 E4M3、重みだけ、出力チャネルごとの対称スケール（compressed-tensors の `float-quantized`） |
| 道具 | `experiments/k2-quant`（commit `2961fef`）。`--pattern` で lm_head を外した |
| 変換 | 2 台それぞれ、推論用のイメージのコンテナの中で CPU だけ（`--network none`）。約 8.5 分 |
| 結果 | 19 ファイル、196,347,880,830 バイト。2 台の道具のマニフェストは、バイト単位で一致した |
| 照合 | `serve verify` で、2 台とも 19 ファイルがマニフェストと合った |

## lm_head

最初に作った `k2s1`（lm_head も FP8）は、起動できなかった。vLLM 0961bbae では、FP8 の `ParallelLMHead` を humming の線形カーネルで読めず、`AttributeError: 'ParallelLMHead' object has no attribute 'output_partition_sizes'` で落ちた（#68）。lm_head の FP8 は、K2 の第 2 段（vLLM の修正）と一緒に扱う。

## 読み込み方

変換と照合の直後に `--load-format instanttensor` で起動すると、`buffer_size (1268776960 B) exceeds device memory budget (649068544 B)` で、2 台とも重みの読み込みの最初で落ちた。大量の読み書きのあとでページキャッシュが埋まり、GPU の空きが小さく見えたためと見ている（推測。GB10 は CPU と GPU がメモリを共有する）。そのため、今回は `--load-format auto`（mmap）で起動した。重みの読み込みは約 520 秒だった。

## 品質（探り）

要約は [N = 0](20260926T125314Z-p2-nope-tp2-full-o9ozyg/summary.md)、[N = 3](20260926T131449Z-p2-nope-tp2-mtp3-xggdon/summary.md)。

| 条件 | N = 0 | N = 3 |
|---|---:|---:|
| `quality/toolcall` | 5 / 5 | 5 / 5 |
| `quality/code/humaneval+`（1 問、上限 1024） | 0 / 1（上限で切れた） | 1 / 1 |
| `quality/needle/8k/d50` | 1 / 1 | 1 / 1 |

toolcall の 5 問は、どちらも、2026-09-23 の投機なしの基準の回と、正解・不正解が同じだった。humaneval+ の 1 問（HumanEval/0）は、基準の回でも上限 1024 で切れる問題である。
