# ゴールに直結する作業だけをする

`PLAN.md` の成功の基準（§3）と段階（§4）に直結する作業だけをする。

- 作業を始める前に、それが成功の基準のどの項目を、どう前に進めるかを言えること。言えない作業はしない。
  - 例: 「コード・英語の decode の速さ（60 tok/s）に効く」「P6 の自動起動の終わりの条件に効く」。
- ゴールに直結しない改善・調査・整理は、ゴールの作業を止めている場合だけ行う。止めていないなら、`gh issue create` で起票して後に回す。
- ボーイスカウトルール（`boy-scout.md`）の小さな直しも、本題の作業の中で触れた箇所に限る。直しのための作業を別に起こさない。

## 計測

- 計測を提案・実行する前に、所要の時間と「その計測で何が決まるか（次の判断にどう効くか）」を示す。次の判断に要らない計測はしない。
- 各段階・各タスクは、少ないサンプル数（探り `probe`、確認 `fast`）で完了とする。
- 大量のサンプル数の計測（`quick` 以上の quality、agent の 300 試行、72 時間の連続稼働など）は、完了の条件にしない。`PLAN.md` の P8（最終の検証）でまとめて行う。
- issue の受け入れ基準と TAKT への依頼にも、長時間の試験を入れない。
