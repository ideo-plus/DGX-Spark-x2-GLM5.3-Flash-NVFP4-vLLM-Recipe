# ボーイスカウトルール

作業中に見つけた汚れ (古い記述、誤り、置き場所の悪い文、重複など) は、少しずつ直してよい。

- 本題を優先する。本題の差分に混ぜず、小さく独立したコミットにする。
- 影響が大きいもの、危険なもの、実機の状態に触れるものは、その場で直さず `gh issue create` で起票する。
  `CLAUDE.md` の「このリポジトリの試験の方針の例外」に挙げた試験の契約に触れるものも同じ。
- コードと試験の準備が要るものは、`CLAUDE.md` の「現在の開発手順」のとおり takt に回す。
- takt の作業では、依頼が定めた書き込み範囲を優先する。範囲外で見つけた汚れは完了報告に書くだけにする。
