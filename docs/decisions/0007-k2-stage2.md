# ADR 0007: K2 の第 2 段（アテンションの射影と lm_head の FP8）の進め方

- 日付: 2026-09-26
- 状態: 採用
- 関係: [ADR 0006](0006-path-pruning.md)（K2 を残した）、[第 1 段の記録](../results/2026-09-26-k2-stage1.md)、[調査](../research/2026-09-26-k2-quant-survey.md)、#68

## 背景

第 1 段（dense と共有の専門家を FP8）で、vLLM を直さずに「変換 → 取り込み → 照合 → 読み込み」が通り、投機なしで 9〜11% 速くなった（1 ステップ約 71 → 約 65 ms）。

残りの BF16 の量（1 台、1 ステップあたり。調査の §1）は、次のとおり。

| 部分 | BF16 | 今の vLLM で量子化できない理由 |
|---|---:|---|
| KDA の射影 ×34 | 4.72 GB | `Glm5NextLinearAttention.__init__` が `quant_config` を外す（`vllm/models/glm5next/common/kda.py:188-194`） |
| MLA の射影 ×11 | 1.20 GB | `quant_config=None` を渡す（`vllm/models/glm5next/common/model.py:330`） |
| lm_head | 0.63 GB | humming の線形カーネルが `ParallelLMHead` の `output_partition_sizes` を前提にする（#68） |
| indexer ×11 | 0.29 GB | MLA の `None` を受け継ぐ |

第 1 段の実測では、読む量を約 0.75 GB 減らして約 6 ms 短くなった（約 8 ms / GB）。同じ比で見積もると、FP8 で半分にしたときの短縮は次のとおり【推定】。

- KDA で約 19 ms
- MLA で約 5 ms
- lm_head で約 2.5 ms（N = 3 では、下書きのたびに読む分も縮む）

さらに、`packed_modules_mapping` には `gate_up_proj` しかない（`model.py:1046-1048`）。KDA のまとめた層 `in_proj_qkvbfg_a`（q・k・v・b は分割、f_a・g_a は TP の 2 台で複製）と、MLA の `fused_qkv_a_proj` は、compressed-tensors の scheme の引き当てに要る対応が無い。

## 決めたこと

1. **2 段に分ける。**
   - **2a:** 次を FP8 にする。いずれも vLLM で使われ慣れた層の形である。
     - lm_head（#68 の修正）
     - MLA の射影（`fused_qkv_a_proj`、`q_b_proj`、`o_proj`）
     - KDA のうち、まとめていない射影（`o_proj`、`f_b_proj`、`g_b_proj`）
   - **2b:** KDA のまとめた層 `in_proj_qkvbfg_a` を FP8 にする。複製の分割を含むので、スケールの読み込みの危険が高い。2a で速さと品質を確かめてから進める。
2. **vLLM の直し方は、イメージを作り直さず、直した Python のファイルを重ねる。**
   - 直すのは Python のモデルのコードと量子化の層だけで、CUDA のカーネルは変えない。今のイメージ（`sha256:9df45888…`）はそのままにする。
   - 直したファイルは `serving/payload/` の下に置き、`serve push` で配る。構成の `--mount type=bind,...,readonly` で、コンテナの中の該当のファイルに重ねる。
   - 根拠として、次の 2 つを試験で固定する。
     - 直したファイルが「固定した vLLM のソース（0961bbae）＋コミットしたパッチ」と一致すること。
     - 重ねる先の道筋が、イメージの中のファイルと一致すること。
   - イメージの作り直し（前回は約 34 分）が要らず、探りの回が速くなる。上流へ返すときは、同じパッチを PR にする。
3. **実装は Opus で行う。** vLLM の内部の量子化の経路に手を入れる、危険の高い実装なので、TAKT のこの作業に限り、実装の段を Opus（t2）にする（その worktree の `.takt/runtime.yaml` だけを変え、コミットしない）。
4. **確かめ方は、第 1 段と同じ 3 段にする。** 探り（`probe`）→ 確認（`fast`）→ 記録。
   - 比べる基準は `k2s1b`。
   - 起動は、変換の直後なら `--load-format auto` で行う（ページキャッシュの件）。
   - 壊れの印、toolcall の一致、needle は、どの段でも見る。

## 考えたが採らなかった案

- **イメージを作り直す:** 1 回約 34 分かかる。直すのが Python だけなので、得るものが少ない。
- **KDA のまとめた層から始める:** 効果は最大（約 19 ms のうちの大半）だが、危険も最大である。まず 2a で、パッチの形と確かめ方を固める。
- **NVFP4（W4A16）にする:** 読む量はさらに半分になるが、較正が要る。まとめた層では、全体のスケールを射影どうしで共有させる必要がある（`compressed_tensors_w4a4_nvfp4.py:100-113`）。FP8 で通してから考える。
